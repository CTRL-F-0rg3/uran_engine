1//! Import modeli 3D: `.obj` + `.mtl` z teksturami oraz `.glb` (glTF 2.0).
2//!
3//! ## Obsługiwane formaty
4//!
5//! | Format | Status | Uwagi |
6//! |--------|--------|-------|
7//! | `.obj` + `.mtl` + `.png` | ✅ pełne wsparcie | statyczne bryły |
8//! | `.glb` (glTF 2.0) | ✅ siatka + materiały + szkielet | patrz `gltf` |
9//! | `.gltf` + osobne pliki | ❌ | wymaga czytania z dysku |
10//! | `.fbx`, `.blend` | ❌ | właścicielskie formaty Blendera |
11//!
12//! ## Dlaczego glTF jest osobnym modułem
13//!
14//! Oba formaty mają wspólne tylko „czytają wierzchołki". glTF przy okazji
15//! niesie szkielet, wagi skinningu i materiały PBR, więc ma własny format
16//! wierzchołka (`gltf::SkinVertex`, 64 B) i własny potok renderujący
17//! (`crate::skin`). Mieszanie tego z `Vertex` (44 B) rozszerzyłoby każdą
18//! bryłę świata o 55% rozmiaru wierzchołka — za cenę, której płaciłby
19//! kod w ogóle niemający postaci.
20//!
21//! ## Ścieżka użycia
22//!
23//! ```no_run
24//! let mut model = uran_render3d::import::obj::load_from_file("bike.obj")?;
25//! model.scale_to_height(1.2);          // motocykl ~1.2 m wysoki
26//! for part in &model.parts {
27//!     println!("{} — {} materiał: {}", part.name,
28//!              part.mesh.vertices.len(), part.material.name);
29//! }
30//! # Ok::<(), Box<dyn std::error::Error>>(())
31//! ```
32//!
33//! ```no_run
34//! let ch = uran_render3d::import::gltf::load_from_file("postac.glb")?;
35//! println!("{} kości, {} siatek", ch.joints.len(), ch.meshes.len());
36//! # Ok::<(), Box<dyn std::error::Error>>(())
37//! ```
