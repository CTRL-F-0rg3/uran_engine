Przegląd

Uran Engine to niewielki silnik 2D napisany w Rust, zbudowany na wgpu (render) i winit (okno). Łączy w jednej fasadzie: okno, ECS, wejście, rysowanie natychmiastowe i tilemapy.

Silnik dzieli się na małe crate'y w workspace:

CrateRola
uran-mathWektory (glam), Color, Rect.
uran-coreOkno (windowed), czas, wejście (Input, Key).
uran-assetŁadowanie obrazów/czcionek, cache po ścieżce, find_asset_dir.
uran-ecsŚwiat ECS (hecs) + komponenty graficzne (Sprite, Mesh…).
uran-renderRysowanie 2D (batching), kamera, tekst, tekstury, postfx.
uran-tilemapMapy kafli: warstwy, tilesety, autotiling, kolizje, XML.
uran-engineFasada — jeden use uran_engine::prelude::*; daje całość.

Do silnika dołączone są dwa narzędzia:

  • uran (CLI) — tworzy projekty i elementy gry z terminala.
  • uran-editor — graficzny edytor map kafli.

Szybki start

Pracę zaczynasz od narzędzia uran, które działa jak cargo new nazwa --bin, ale dodatkowo kopiuje silnik:

# z katalogu silnika (uran_engine/)
cargo run -p uran-cli -- new moja-gra --engine .

# albo po zbudowaniu
cargo build -p uran-cli
./target/debug/uran new moja-gra --engine . --at ~/gry

Powstaje katalog moja-gra/ z gotowym projektem:

moja-gra/
├── Cargo.toml          # zależność: uran-engine = { path = "engine/uran-engine" }
├── engine/             # skopiowany silnik (samodzielny workspace)
├── assets/
│   └── maps/
└── src/
    ├── main.rs         # punkt wejścia: App + okno
    ├── object.rs       # centralny rejestr obiektów
    ├── init.rs         # centralna inicjalizacja
    └── elements/
        └── mod.rs      # rejestr elementów gry

Uruchamiasz grę standardowo:

cd moja-gra
cargo run

Struktura projektu

Wygenerowany projekt dzieli grę na trzy warstwy:

  • src/main.rs — tworzy App, okno i podpina init (raz) oraz object (co klatkę).
  • src/init.rs / src/object.rs — centralne punkty, które wywołują init / update każdego elementu.
  • src/elements/<nazwa>/ — pojedynczy element gry (object.rs, init.rs i skrypty data/).
ZasadaLogikę trzymasz w skryptach elementu. Pliki centralne (object.rs/init.rs) tylko je spinają — dlatego dodawanie nowego elementu to jedno polecenie, bez grzebania w pętli głównej.

App i cykl życia

App to punkt startowy. Buduje się go łańcuchowo (builder), a na końcu woła run(). Systemy działają w kolejności rejestracji.

use uran_engine::prelude::*;

fn main() {
    App::new()
        .window(windowed(1280, 720).title("Moja gra").vsync(true))
        .add_startup_system(|ctx: &mut Ctx| {
            // raz, po utworzeniu renderera: ładuj assety, buduj świat
        })
        .add_system(|ctx: &mut Ctx| {
            // co klatkę: logika + rysowanie
        })
        .run();
}

.add_system(f)System uruchamiany co klatkę.

Opis okna

windowed(szerokość, wysokość) zwraca WindowDescriptor:

windowed(1280, 720)
    .title("Tytuł")
    .resizable(true)
    .background(0x0A0C12)      // kolor tła (hex RRGGBB)
    .vsync(true)
    .samples(4)                // MSAA: 1, 2 lub 4
    .cursor_visible(true)
Systemy a stanStan gry trzymasz w zmiennej złapanej przez closure (move |ctx| …). System to FnMut(&mut Ctx), więc może mutować stan między klatkami.

Rysowanie (Graphics)

ctx.gfx to „pędzel" w trybie natychmiastowym — wywołania trafiają do listy rysowania i renderują się w tej samej klatce. Współrzędne są w jednostkach świata (oś Y w górę), chyba że przełączysz się w screen_space().

ctx.gfx
    .color(Color::RED)
    .layer(10)
    .draw_rect(Rect::from_xywh(0.0, 0.0, 100.0, 50.0));

ctx.gfx.draw_line(Vec2::ZERO, Vec2::new(100.0, 0.0), 2.0);
ctx.gfx.draw_circle(Vec2::new(50.0, 50.0), 20.0);

.layer(n)Warstwa sortowania — wyższa = na wierzchu.
.blend(b)Tryb mieszania (Alpha, Additive…).
.draw_rect(r)Wypełniony prostokąt.
.draw_rect_outline(r, w)Obrys prostokąta.

.draw_circle(c, r)Koło wypełnione.
.draw_polygon(pts)Wielokąt z listy punktów.
.draw_texture(tex, rect, uv)Tekstura (region UV) w prostokącie.
.draw_text(font, txt, pos, size, align)Tekst.
.screen_space()Przejście do UI (0,0 = lewy górny, Y w dół).

Kolory

let c = Color::from_hex(0xFF5500);      // hex RRGGBB
let c = Color::rgba(1.0, 0.0, 0.0, 0.5); // z alfą
// gotowe stałe: WHITE, BLACK, RED, GREEN, BLUE, YELLOW, CYAN, MAGENTA…
c.with_alpha(0.5).multiply(0.8).lerp(Color::WHITE, 0.5)

Tekst

ctx.gfx.screen_space();
if let Some(font) = ctx.font {
    ctx.gfx.color(Color::WHITE).draw_text(
        font, "Wynik: 100", Vec2::new(16.0, 16.0), 20.0, TextAlign::Left);
}
Prostokąty i wektoryRect::from_xywh(x, y, w, h), Rect::from_center(środek, rozmiar); wektor to glamowy Vec2 (Vec2::new, Vec2::ZERO, Vec2::splat, .length(), .normalize_or_zero()).

Wejście (Input)

ctx.input to migawka wejścia z bieżącej klatki. Rozróżnia stan „przytrzymany" (pressed) od „wciśnięty w tej klatce" (just_pressed).

if ctx.input.just_pressed(Key::Space) { /* skok */ }
if ctx.input.pressed(Key::KeyW) { /* trzyma W */ }

let dir = ctx.input.axis(Key::KeyA, Key::KeyD);  // -1..1
let mx = ctx.input.mouse_position();            // pozycja (ekran)
let world = ctx.mouse_world();                 // pozycja (świat)
if ctx.input.mouse_just_pressed(MouseButton::Left) { /* klik */ }

Najważniejsze metody

MetodaOpis
.pressed(Key) / .just_pressed(Key)Klawisz trzymany / wciśnięty teraz.
.just_released(Key)Klawisz puszczony w tej klatce.
.mouse_pressed(M) / .mouse_just_pressed(M)Przycisk myszy.
.mouse_position()Pozycja kursora w pikselach ekranu.
.mouse_delta()Ruch myszy między klatkami.
.scroll_delta()Ruch kółka (zwraca Vec2).
.axis(neg, pos)Oś -1..1 z dwóch klawiszy.
.control() / .shift() / .alt()Modyfikatory.
.primary_pressed()Lewy przycisk (alias).

Key to fizyczny kod klawisza (winit): KeyW, KeyA, Space, Escape, Enter, Tab, ArrowLeft/Right/Up/Down, Digit1…Digit9, BracketLeft/Right. Mouse to MouseButton (Left, Right, Middle).

Kamera 2D

Camera2d to projekcja ortograficzna z osią Y w górę. Domyślnie zoom = 1.0 oznacza, że 1 jednostka świata = 1 piksel.

ctx.camera.position = Vec2::new(100.0, 50.0);  // środek widoku
ctx.camera.zoom = 2.0;                        // powiększenie

let view = ctx.camera.visible_rect(ctx.window.size); // co widać
let p = ctx.camera.screen_to_world(mx, ctx.window.size);
MetodaOpis
visible_rect(okno)Widoczny prostokąt świata.
visible_size(okno)Rozmiar widoku w jednostkach świata.
screen_to_world(p, okno)Ekran → świat.
world_to_screen(p, okno)Świat → ekran.
fit_world(rect, okno)Ustawia zoom/pozycję na cały obszar.
clamp_to_bounds(rect, okno)Nie pokazuje pustki poza światem.
smooth_follow(cel, dt, prędkość)Płynne podążanie za celem.
Kamera za graczemw systemie wywołaj ctx.camera.position = gracz.pos; (albo smooth_follow) i wszystko, co rysujesz w przestrzeni świata, samo się przewinie.

Assety

Obrazy i czcionki ładujesz przez ctx; zwracają lekkie uchwyty (Handle), więc nie kopiujesz danych. Wynik jest cache'owany po ścieżce.

if let Some(tex) = ctx.load_image("tiles/terrain.png") {
    ctx.gfx.draw_texture(tex, Rect::from_xywh(0.0, 0.0, 64.0, 64.0), UvRect::FULL);
}
let font = ctx.load_font("fonts/DejaVuSans.ttf");
  • Handle<Image> (alias Texture) — tekstura.
  • Handle<FontData> (alias Font) — czcionka.
  • UvRect::FULL — cała tekstura; region wycinasz przez UvRect.
Katalog assetówdomyślnie assets/. Możesz go zmienić przez App::assets(path). Funkcja find_asset_dir() szuka katalogu assets idąc w górę — dzięki temu cargo run -p gra działa z dowolnego katalogu roboczego.

ECS (World)

ctx.world to świat ECS (hecs): encje + komponenty. Komponenty graficzne (Sprite, Transform, Mesh, Material…) renderują się automatycznie.

let entity = ctx.world.spawn((
    Transform { pos: Vec2::new(100.0, 100.0), ..Default::default() },
    Sprite { texture: tex, ..Default::default() },
));

// zapytanie o komponenty
for (_, (transform,)) in ctx.world.query::<(&mut Transform,)>().iter() {
    transform.pos += Vec2::new(1.0, 0.0);
}
ECS czy closure?W tym silniku ECS jest opcjonalny. Do prostych gier wystarczy stan w closure systemu (patrz App); ECS przydaje się, gdy masz wiele podobnych obiektów (armie, cząsteczki). Wybierz prostsze narzędzie.

Tilemapa

Mapa kafli to arkusz (Tileset) + warstwy (Layer) + kolizje. Najprościej wczytujesz mapę z XML, a potem rysujesz i sprawdzasz kolizje:

let mut map = ctx.load_tilemap("maps/farm.xml").unwrap();

// rysowanie (co klatkę)
map.draw(&mut ctx.gfx, ctx.camera.visible_rect(ctx.window.size));

// kolizja gracza
if map.overlaps_solid(gracz_rect) { /* cofnij ruch */ }

// odczyt / zapis kafla
let t = map.tile_at(0, x, y);
map.set_tile(0, x, y, 12);

Budowa mapy w kodzie

let mut map = TileMap::new("farma", 32.0, 40, 30);
map.add_tileset_from_image("terrain", ctx.assets, "tiles/terrain.png", 32, 0, 0);

let podloga = map.add_layer(Layer::new("ground", "terrain", 40, 30).as_editable());
let sciany   = map.add_layer(Layer::new("walls",  "terrain", 40, 30).as_solid());

// wypełnienie i kolizja
map.layers[podloga].tiles.fill_rect(0, 0, 40, 30, 1);
map.set_tile(sciany, 5, 5, 9);
map.set_props(sciany, 5, 5, TileProps::SOLID);

map.save_xml("assets/maps/farm.xml");

Właściwości kafli (TileProps) to flagi bitowe: SOLID (blokada), WATER (woda), FARMLAND (uprawa), REMOVABLE, PLACEABLE, WATERABLE.

Format XML mapy

Mapy zapisują się w czytelnym XML — możesz je edytować też ręcznie.

<map name="farma" tile-size="32" width="40" height="30">
  <spawn x="8" y="6"/>
  <edit-area x="4" y="4" width="12" height="10"/>
  <tileset name="terrain" src="tilesets/terrain.png" tile-size="32"/>

  <layer name="ground" tileset="terrain" editable="true">
    <row y="0">1 1 1 1 . . 2 2</row>
  </layer>

  <layer name="walls" tileset="terrain" solid="true">
    <props x="3" y="3">solid</props>
  </layer>
</map>
  • . w wierszu = pusty kafel; liczby to indeksy w arkuszu (od lewej góry).
  • Wiersz y="0" jest najbliżej dołu (oś Y w górę).
  • Atrybuty warstwy: solid, editable, hidden, width/height (gdy różne od mapy).
  • <props> przyjmuje listę nazw: solid water farmland….
  • <autotile base="…" mode="exact|presence"/> — automatyczne brzegi terenu.

Edytor map

Graficzny edytor (uran-editor) pozwala rysować mapy kafli na wielu warstwach bez pisania XML. Uruchamiasz go z argumentami:

# nowa mapa + arkusz kafli
cargo run -p uran-editor -- --new 32 24 32 --tileset terrain assets/tilesets/terrain.png 32

# otwarcie istniejącej mapy
cargo run -p uran-editor -- --map assets/maps/farm.xml

Flagi:

  • --new <w> <h> [rozmiar_kafla] — nowa mapa.
  • --map <ścieżka.xml> — wczytaj mapę.
  • --tileset <nazwa> <plik.png> <rozmiar_kafla_px> — dodaj arkusz.

Elementy gry (object / init / data)

Element to samodzielny fragment gry. Tworzysz go jednym poleceniem:

./target/debug/uran element przeciwnik   # w katalogu projektu

Powstaje katalog:

src/elements/przeciwnik/
├── mod.rs      # pub mod data; pub mod init; pub mod object;
├── object.rs   # update(ctx) — co klatkę
├── init.rs     # init(ctx)   — raz na starcie
└── data/
    ├── mod.rs
    ├── a1.rs … z9.rs   # 234 puste szablony do wypełnienia

Każdy skrypt data/<id>.rs to pusty szablon z dwiema funkcjami:

use uran_engine::prelude::*;

pub fn init(_ctx: &mut Ctx)   { // raz na starcie }
pub fn update(_ctx: &mut Ctx) { // co klatkę }
Jak to spinaćWypełniasz szablon (animacje, logika), a on już jest podpięty: object.rs elementu wywołuje data::a1::update… data::z9::update, a centralne src/object.rs/src/init.rs wywołują object::update/init::init całego elementu. Dodajesz własny skrypt w data/ i dopisujesz wywołanie — reszta dzieje się sama.

Centralne pliki zawierają markery, wokół których CLI dopisuje wywołania:

// src/object.rs
pub fn update_all(ctx: &mut Ctx) {
    elements::przeciwnik::object::update(ctx);
    // [uran:calls]
}
